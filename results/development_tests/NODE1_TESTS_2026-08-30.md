# Node1 development tests — 2026-08-30

These are RTX 3090 software-telemetry development tests at the node1 200 W
power cap. GPU 0 was quarantined and never used. Every accepted run logged
NVML and DCGM, performed real useful work, and passed missingness, alignment,
six-of-six marker, and checksum checks. Node1 has no connected PicoScope
current channels, so these tests do **not** measure SensorGuard physical-sensor
gain. The sealed fused-update family was not run.

## Two-seen/one-model-unseen result

The lightweight two-stage random forest used 30 s windows, 15 s stride, and
the fixed 3-of-5 rule at probability 0.85. Timing shaping and interleaving were
the seen families. The three GPU3 memory-minimal runs were excluded from all
fitting and used only as the model-unseen target. Fit and control-test GPUs are
disjoint, and the sealed fused-update family is absent.

| Seen evasion data | Target | TP / FN | Run TPR | Window AUC | False alerts / control GPU-hour | Time to alert |
|---|---|---:|---:|---:|---:|---|
| Timing shaping | Memory minimization | 0 / 3 | 0% | 0.968 | 0 / 0.843 h = 0 | All right-censored |
| Interleaving | Memory minimization | 0 / 3 | 0% | 0.992 | 0 / 0.843 h = 0 | All right-censored |
| Both seen families | Memory minimization | 0 / 3 | 0% | 0.986 | 0 / 0.843 h = 0 | All right-censored |

The maximum training probabilities on the unseen runs were 0.351–0.552, well
below 0.85. High window AUC but zero run alerts means the model ranks the
signals but the fixed operating point does not transfer. Adding the second
seen evasion family did not solve this. This is a useful negative development
result, not a final SensorGuard accuracy result.

  test and then completed three valid repetitions.
- No other user process was stopped, and node1 GPU 0 was not reset or used.

## Six-PicoScope logger overhead on verifier

Five paired repetitions streamed all six attached PicoScopes (12 channels) at
10 kS/s while comparing the same steady RTX 3090 GEMM with and without the
physical logger. Condition order alternated between baseline-first and
logger-first. Every 90 s acquisition returned all six scopes with no driver
overflow and no channel-A clipping.

The mean useful-work penalty was **-0.045%** (standard deviation 0.248%; 95%
Student-t interval **-0.353% to 0.262%**). The negative point estimate is
measurement noise, so the supported conclusion is **no measurable physical
logger throughput overhead at this experiment's resolution**, not negative
overhead. Mean logger CPU use was 14.28% of one core-equivalent while streaming
all six units, and raw output was 863.49 MB per monitored GPU-hour at 10 kS/s.
The five authoritative rows are in
`../physical_overhead_20260830/pico_overhead_repetitions.csv`.

This overhead test is independent of rail identity: it exercises passive
acquisition but does not establish which scope channel maps to which GPU. The
acquisition used the code at commit `7bbd9c4`; summary-only aggregation used
`8e5baa9`. The verifier checkout itself remained on its older commit to preserve
Robi's untracked data.

## Live electrical mapping attempt

The documented design says three two-channel oscilloscopes cover six RTX 3090
GPUs, but the live verifier enumerates six distinct PicoScope serial numbers.
Two blinded one-GPU-at-a-time passes were therefore run with reverse activation
orders. Both 300 s captures returned all six scopes without overflow or
channel-A clipping. Host clocks agreed within 2 ms, every usable GPU marker
started within 0.5 ms of schedule, and the 20 s markers did not overlap.

Only node1 GPU 1 repeated on the same top-ranked channel (`12789/2929`, channel
A). The top channel changed between passes for node1 GPUs 2--4 and verifier GPU
0. Node1 GPU 0 could not be activated because it still requires reset. The live
map therefore **fails replication and must not be used for paper acquisition**.
The audit table is `../electrical/channel_map.csv`; exact marker timestamps are
under `../electrical/mapping_live_20260830*/markers/`.

This result shows that USB/API availability and passive streaming are healthy,
but does not establish that the probes are attached to the GPUs we activated.
Robi or Martin must identify the present scope serial/channel/GPU wiring (and
explain the three-versus-six-scope discrepancy) before synchronized electrical
attack collection.

A stronger follow-up used five 6 s heavy-GEMM / 6 s idle cycles per usable GPU.
Every provisional top channel increased during all five heavy-load intervals:
node1 GPU 1 mapped to `12789/2929 A`, GPU 2 to `13239/1303 B`, GPU 3 to
`13239/2968 B`, GPU 4 to `13239/0093 B`, and verifier GPU 0 to `13239/2968 A`.
The GPU 1, GPU 2, and GPU 4 responses are useful provisional matches. GPU 3 and
verifier GPU 0 have weak separation from their second-ranked channels, and
node1 GPU 0 is still unavailable. The pulsed result therefore narrows the map
but does not make R04 complete. Its auditable summary is
`../electrical/channel_map_pulsed.csv`.

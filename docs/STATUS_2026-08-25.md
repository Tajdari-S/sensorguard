## Key technical findings (E1 earned its keep)

The calibration health gates caught five real defects before any corpus data
depended on them:

1. **Serial NVML sampling breaks alignment on multi-GPU hosts.** The two PCIe
   throughput queries block ~20 ms each by NVML design; sampling GPUs serially
   pushed GPU≥1 receipt jitter to 100–300 ms (over the frozen 100 ms limit).
   Fixed: parallel per-GPU threads + receipt stamped before the blocking
   queries. Alignment now ~18–70 ms worst case.
2. **CUDA device order ≠ NVML order on mixed-VBIOS hosts.** CUDA's default
   FASTEST_FIRST ordering diverged from PCI order on node2, so the load marker
   burned a different physical GPU than the one being health-checked — caught
   by the blinded-activation check exactly as the protocol intended. Fixed:
   `CUDA_DEVICE_ORDER=PCI_BUS_ID` forced by the supervisor.
3. **DCGM profiling-class fields are unsupported on GeForce.** Fields
   1009/1010 (PCIe throughput) made `dcgmi dmon` fail with error -36; a lenient
   health check initially passed the garbage. Fixed field set + hardened check;
   PCIe rates stay NVML-only. DCGM data recorded before commit 80fd457 is
   invalid.
4. **Unsynced GEMM enqueue races ahead of throttled GPUs.** The load marker
   queued ~525 GEMMs in a 2 s burst window; node2 gpu4 drained them in 74 s and
   blew the marker timeout. Fixed: per-iteration synchronize.
5. **node2 gpu4 thermally throttles** to ~915 MHz at 76 °C / 228 W under
   sustained load (technician item). Counters and self-pacing workloads are
   unaffected; wall-clock-sensitive measurements should avoid this GPU.

Also fixed in tooling: roofline NCU parser used last-kernel-wins flattening
(init kernels could overwrite the benchmark kernel's DRAM bytes — now
per-launch, dominant kernel, median) and benchmarks defaulted to fp16 against
an fp32 ceiling (now explicit fp32).
